# Dashboard Question Launcher Design

## 목표

대시보드를 Jarvis의 핵심 기능인 근거 기반 질문으로 진입하는 첫 화면으로 만든다. 대시보드 안에서 답변을 생성하지 않고, 질문을 시작하면 Ask AI 작업 화면으로 이동하게 해 두 화면의 역할 중복을 피한다.

## 역할 경계

### 대시보드

- 사용자가 질문을 시작하는 진입점이다.
- 추천 질문과 최근 대화를 보여준다.
- 최근 등록된 공개 Wiki 근거를 요약해서 보여준다.
- 답변 스트리밍, 출처 카드, 후속 질문은 표시하지 않는다.

### Ask AI

- 실제 대화가 진행되는 작업 화면이다.
- 대화 목록, 답변 스트리밍, 출처 카드, 후속 질문을 전담한다.
- 대시보드에서 전달받은 질문은 Ask AI가 열린 직후 한 번만 자동 전송한다.

## 화면 구성

### 1. 질문 시작 영역

- 제목: `무엇을 확인할까요?`
- 설명: `공식 근거와 기준일을 함께 찾아드립니다.`
- 기존 Ask 입력 UI와 동일하게 `Enter` 전송, `Shift+Enter` 줄바꿈을 지원한다.
- 추천 질문 4개를 입력창 아래에 배치한다. 추천 항목을 누르면 즉시 과금 요청을 보내지 않고 입력창에만 채운다.
- 전송하면 대시보드에 답변을 표시하지 않고 `/ask`로 이동한다.

초기 추천 질문은 현재 Wiki 자료와 직접 연결되는 다음 주제를 사용한다.

- 식대 비과세 한도는?
- 퇴직소득 원천징수 절차는?
- 일용근로자 지급명세서 제출기한은?
- 종업원분 주민세 면세점은?

### 2. 최근 질문

- 현재 사용자가 소유한 최근 대화 최대 5개를 표시한다.
- 제목과 마지막 갱신 시각을 보여준다.
- 항목을 누르면 `/ask/{conversationId}`로 이동한다.
- 대화가 없으면 `첫 질문을 시작해 보세요.`라는 짧은 빈 상태를 표시한다.

### 3. 최근 근거

- 게시된 Wiki 페이지 중 최근 갱신된 항목 최대 5개를 표시한다.
- 제목, 문서 유형, 갱신일을 보여준다.
- 항목을 누르면 해당 Wiki 문서로 이동한다.
- 운영 지표나 관리자 전용 검토 수치는 넣지 않는다. 대시보드는 모든 역할이 공통으로 사용하는 화면이기 때문이다.

## 시각 디자인

- 기존 `PageShell`, 테마 변수, Kinetic Grid/Blinking Squares 배경을 유지한다.
- 질문 시작 영역은 가장 큰 카드로 배치하고, 아래는 `최근 질문`과 `최근 근거` 2열 카드로 구성한다.
- 카드는 완전 불투명하게 덮지 않고 기존 배경이 아주 옅게 보이는 surface 색을 사용한다.
- 화면 전체를 카드로 채우지 않는다. 1200px 내외의 콘텐츠 폭과 충분한 외곽 여백을 유지하되, 현재 한 장짜리 카드보다 정보 밀도를 높인다.
- 모바일에서는 모든 영역을 1열로 쌓는다.

## 데이터 흐름

1. 대시보드 서버 컴포넌트가 세션을 확인한다.
2. 최근 대화 5개와 최근 게시 Wiki 5개를 병렬 조회한다.
3. 질문 시작 컴포넌트는 사용자가 입력한 draft를 `sessionStorage`에 저장하고 `/ask`로 이동한다.
4. Ask 화면의 입력 컴포넌트는 해당 draft를 한 번 읽은 뒤 즉시 삭제하고 기존 `/api/ask` 흐름으로 제출한다.
5. 대화 생성, 메시지 저장, CLI Proxy 호출, 출처 검증은 기존 Ask API만 담당한다.

질문 본문을 URL query string에 넣지 않는다. 브라우저 기록, 서버 로그, 분석 도구에 질문이 남는 범위를 줄이기 위해서다.

## 컴포넌트 경계

- `DashboardAskLauncher`: 입력, 추천 질문 선택, 임시 draft 전달만 담당하는 client component
- `DashboardRecentConversations`: 최근 대화 링크와 빈 상태를 표시하는 server-rendered section
- `DashboardRecentEvidence`: 최근 Wiki 링크를 표시하는 server-rendered section
- 기존 `AskPanel`: dashboard draft를 한 번 소비해 기존 제출 함수로 전달

대시보드에서 Ask API 호출이나 스트림 처리를 새로 구현하지 않는다.

## 오류 처리

- 빈 질문은 전송하지 않는다.
- 입력은 기존 Ask API 제한과 동일하게 2,000자로 제한한다.
- `sessionStorage` 접근이 실패하면 Ask 화면으로 이동하지 않고 입력창 아래에 재시도 안내를 표시한다.
- 최근 대화나 Wiki가 없을 때는 오류처럼 보이지 않는 빈 상태를 표시한다.
- Ask API 또는 CLI Proxy 장애 처리는 기존 Ask 화면의 오류 UI를 그대로 사용하며 별도 fallback을 추가하지 않는다.

## 접근성

- 질문 입력창에는 명시적인 label 또는 `aria-label`을 제공한다.
- 추천 질문은 키보드로 선택 가능한 button으로 구현한다.
- 최근 대화와 Wiki 항목은 의미 있는 링크 텍스트를 사용한다.
- focus-visible 스타일과 테마별 대비를 기존 디자인 토큰으로 유지한다.
- 배경 Canvas는 계속 `aria-hidden`이며 콘텐츠 입력을 막지 않는다.

## 테스트

- 추천 질문을 누르면 입력값만 채워지고 네트워크 요청이 발생하지 않는다.
- Enter는 draft를 저장하고 Ask 화면으로 이동한다.
- Shift+Enter는 줄바꿈하며 이동하지 않는다.
- Ask 화면은 draft를 한 번만 제출하고 저장소에서 즉시 제거한다.
- 최근 대화와 최근 Wiki가 각각 최대 5개만 표시된다.
- 데이터가 없을 때 두 빈 상태가 표시된다.
- 기존 Ask 대화 생성·스트리밍·출처 검증 테스트는 그대로 통과한다.

## 제외 범위

- 대시보드 내부 채팅 답변 및 스트리밍
- 관리자 KPI, LLM 사용량, 검토 대기열 통계
- 새로운 API endpoint 또는 LLM 호출 경로
- 추천 질문 개인화 및 자동 생성

## 수용 기준

- 첫 화면에서 질문을 입력하고 Ask AI로 자연스럽게 이동할 수 있다.
- 대시보드와 Ask AI가 같은 답변 UI를 중복해서 제공하지 않는다.
- 최근 대화와 최근 근거가 실제 사용자·Wiki 데이터로 표시된다.
- 기존 세 가지 테마와 light/dark mode에서 레이아웃과 대비가 유지된다.
- 모바일과 데스크톱에서 빈 공간이 과하지 않고 배경 효과가 은은하게 보인다.
